# AI 协作、工程过程与风险

## 两种 Agent

- **coding agent**：开发工具，可起草代码、测试和文档；本项目当前的大部分初稿由 coding agent 生成。
- **自然语言业务 Agent**：面向平台使用者、可读懂自然语言并查询/操作预约的可选产品功能。小组尚未决定是否把它纳入课程范围；核心系统不依赖 DSH。

## 组员如何审查 AI 产出

1. 按 `AGENTS.md` 的要求记录目标、限制和验收步骤。
2. 对照课程任务书，逐段阅读涉及的业务规则、权限判断、迁移和前端交互。
3. 实际运行行为测试和端到端演示；让模块 owner 给出修改意见并确认验收证据。
4. 变更经 PR 审查后再合并。AI 生成作者信息、自动测试绿灯和本项目文档均不能替代组员本人签收。
5. 如实记录被采纳/拒绝的 AI 建议、人工改动和实际运行结果；不保存密钥。

## 当前质量门禁

- `uv run ruff check backend`：Python lint。
- `uv run ruff format --check backend`：格式检查。
- `uv run pytest -q`：FastAPI 测试客户端验证业务行为。
- Alembic 在新的空 SQLite 数据库升级到 head。
- GitHub Actions 模板会再以 Compose 启动新 PostgreSQL 实例，执行登录、查座位、幂等预约和冲突验证。
- 生产 workflow 仅手动触发、仅使用已审查标签，并要求 GitHub `production` Environment 审批与 self-hosted runner。

公开 GitHub 仓库已创建。GitHub Actions 已通过代码检查、13 条测试、空库迁移、Compose 测试环境和冒烟流程。生产环境未部署，所有人的人工验收仍待完成。

## 当前风险与应对

| 风险 | 当前处理 | 仍需小组确认 |
| --- | --- | --- |
| 业务政策不完整 | 清单里标出预约范围、申诉、审批和 SLA 待定项 | 联系老师或场地管理员确认并记录证据 |
| 资源状态错乱 | M1/M2/M3 通过来源单号读写占用记录；自动化测试验证重要流转 | 模块 owner 对自己的规则签收，D 与相关 owner 审查跨模块变更 |
| AI 生成权限错误 | 服务端 RBAC；当前行为测试覆盖越权场景 | 组员对每个 API 做人工权限审查 |
| 未签到造成不公平 | 仅新增单次违约记录，不自动累加惩罚 | 申诉、免责和记录保留期需要明确 |
| 通知重复或失败 | 通知使用唯一键；SMTP 失败限次重试且不记录密码 | 真实邮件环境尚未配置/测试 |
| 可选 Agent 误操作 | 预览后确认，执行时重新验证权限与业务条件 | 是否做自然语言层、DSH 插件安装、澄清评估均待投票 |
| 数据隐私 | 演示账号和记录均为虚构数据；屏幕令牌限制在单一房间 | 确认访问日志、邮箱和预约记录的保留期及删除方式 |

更详细的伦理风险见 `docs/ethics.md`；任务书逐条状态见 `docs/requirements.md`。
