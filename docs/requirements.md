## 可选自然语言 Agent

任务书把 Agent 列为附加项。当前另有 `/api/v1/agent/actions/preview` 与 `/confirm`，可供适配层调用；所有写动作需用户确认，并在执行时重新检查权限和业务条件。另有一个 DSH 插件源码包，具备查询、预览和确认工具，但尚未安装或运行。是否把产品 Agent 纳入交付、是否采用 DSH 尚未由小组决定。不要把 coding agent（开发工具）和自然语言业务 Agent 混为一谈。

## 尚待小组或老师确认的业务政策

- 预约可提前多少天、一天内允许的时段和是否允许同一学生的时段重叠。
- 取消预约的截止时点；违约累计规则、申诉/复核和解除机制。当前只记录单次未签到，不自动加重处罚。
- 教室两级审批的真实角色、审批时限、超时处理和特殊教室规则。当前默认 24 小时超时。
- 报修等级、维修 SLA、升级接收人和验收人。当前默认 SLA 为 24 小时，逾期通知管理员。
- 邮件或微信的正式通知渠道、服务账号和实际投递环境。当前提供 SMTP 配置；微信渠道未实现。
- 最长预约参数的允许范围。当前可从 1 调到 24 小时，默认 4 小时；若课程要求严格最多 4 小时，应把上限收紧到 4。
- 真实用户、个人信息、日志保留期以及试运行/生产环境由谁管理。

## 可选 Agent 验收条件（若小组决定实施）

1. 信息不完整时先追问，不猜日期、时间或空间。
2. 查询、申请和取消都只能调用公开业务 API，并按当前用户权限执行。
3. 写操作先显示清楚的摘要，取得确认后再提交；重复确认不重复创建业务记录。
4. 拒绝越权操作；执行失败时如实返回后端结果。
5. 若采用 DSH，安装、配置、调用、权限和部署都纳入流水线与记录。
